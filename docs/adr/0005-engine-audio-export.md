# ADR 0005 — Android engine အသံကို တောင်းမှ ဖိုင်ထုတ်၍ waveform/player/download ပေးခြင်း

- **Status:** Accepted
- **Date:** 2026-10-23
- **ADR 0002 ကို ပြင်ဆင်သည်:** Decision 10 တွင် ပယ်ခဲ့သော `synthesizeToFile` ကို fallback ဖြင့် ပြန်ထည့်သည်။

## Context

Waveform၊ player (pause/seek/ပြန်ဖွင့်) နှင့် download သည် MyanmarTTS တွင်သာ ရှိခဲ့သည်။ Android သည် engine က speaker သို့
ဖတ်နေသော အသံကို app သို့ မပေး — အသံရရန် engine ကို `synthesizeToFile` ဖြင့် ဖိုင်သို့ သီးခြား ထုတ်ခိုင်းရမည်။
Product owner က engine အားလုံးတွင် ရစေရန်၊ မရနိုင်သော engine တွင် fallback ထားရန်၊ နည်းလမ်း သုံးမျိုးထဲမှ
**C (ချက်ချင်းဖတ်၊ တောင်းမှ ဖိုင်ထုတ်)** ကို ရွေးခဲ့သည် (2026-10-23)။

## Decision

1. **Speak** — Android engine သည် ယခင်အတိုင်း ချက်ချင်း အသံထွက်ဖတ်သည် (မစောင့်ရ)။ အဆုံးထိ ဖတ်ပြီးပါက စာ၊ နှုန်း၊ pitch ကို မှတ်ထားပြီး
   Play နှင့် Download ကို ဖွင့်ပေးသည်။ ရပ်လိုက်သော ဖတ်ခြင်းကို မမှတ် (ကြားခဲ့သည်နှင့် မကိုက်၍ — MyanmarTTS နည်းတူ)။
2. **Play/Download နှိပ်မှ** မှတ်ထားသော နှုန်း/pitch (slider ကို နောက်မှ ရွှေ့ထားလည်း) ဖြင့် တူညီသောစာကို app cache ရှိ ယာယီ WAV ဖိုင်
   တစ်ခုတည်းသို့ ထုတ်ခိုင်းသည် (ထုတ်တိုင်း အစားထိုး)။ App ပုံစံ (44-byte header၊ 16-bit mono) သို့ ပြောင်းပြီး MyanmarTTS ၏ player
   ဖြင့် ဖွင့်သည် — waveform၊ pause၊ seek၊ ပြန်ဖွင့်၊ download တူညီစွာ ရသည်။ တစ်ကြိမ်ထုတ်ပြီးပါက ထပ်မထုတ်။
3. **Fallback:** ဖိုင်မထုတ်နိုင်ပါက (engine မစ၊ error၊ ဖိုင်ဗလာ၊ 16-bit PCM မဟုတ်) "ဤ Engine သည် အသံကို မပေးနိုင်" ဟု ပြပြီး
   Play/Download ကို ဖျောက်ကာ ထို engine ကို app ဖွင့်ထားစဉ် မှတ်ထားသည်။ Speak ကိုမူ ဆက်သုံးနိုင်သည်။
4. စာပြင်ခြင်း၊ ထပ်ဖတ်ခြင်း၊ engine ပြောင်းခြင်းသည် ထုတ်နေဆဲ ဖိုင်ကို ရပ်ပြီး (engine queue မပိတ်စေရန်) ရလဒ်ကို လျစ်လျူရှုသည် —
   engine ကို မပံ့ပိုးဟု မမှတ်။
5. flutter_tts ၏ `awaitSynthCompletion` ကို **မသုံး** — plugin source (4.2.5) တွင် engine error နှင့် `stop()` တွင် ထို Future ကို
   ဘယ်တော့မှ မပြီးစေ။ Android `synthesizeToFile` က ERROR ချက်ချင်းပြန်လျှင် callback လုံးဝ မလာ။ ထို့ကြောင့် start/complete/error
   handler ဖြင့် ကိုယ်တိုင် ခြေရာခံပြီး engine မစပါက 5 စက္ကန့်တွင် လက်လျှော့သည်၊ `stop()` က စောင့်နေသူကို လွှတ်သည်။
   Engine စပြီးပါက အချိန်ကန့်သတ်ချက် မထား (နှေးသော engine က စာရှည်ကို ကြာကြာ ထုတ်နိုင်)။
6. ယာယီဖိုင်ကို မထုတ်မီ ဖျက်သည် — engine က "ပြီးပြီ" ဟုဆိုသော်လည်း မရေးခဲ့ပါက ယခင်အသံကို မှားမဖတ်မိစေရန်။ မအောင်မြင်ပါက ဖျက်သည်။
7. Download ဖိုင်အမည် prefix ကို `myanmartts_` မှ `speech_` သို့ ပြောင်းသည် (engine မရွေး တူညီ)။

## Rejected alternatives

- **A. ဖိုင်အရင်ထုတ်ပြီးမှ ဖွင့်ခြင်း:** engine ကို တစ်ကြိမ်သာ ခိုင်းသော်လည်း စာတစ်ခုလုံး ထုတ်ပြီးမှ အသံထွက်သဖြင့် စာရှည်တွင် နှောင့်နှေး၊
  ဖိုင်မထုတ်နိုင်သော engine တွင် ဖတ်တိုင်း (ပထမအကြိမ်) 5 စက္ကန့် စောင့်ရ။
- **B. ဖတ်ပြီးတိုင်း နောက်ကွယ်တွင် ဖိုင်ထုတ်ခြင်း:** မစောင့်ရသော်လည်း Play/Download မသုံးသည့်အခါတိုင်း engine ကို နှစ်ခါ ခိုင်း၍
  battery/data (online voice) အလကား ကုန်။
- **ဖတ်ရင်း speaker အသံကို ဖမ်းခြင်း (AudioPlaybackCapture):** Android 10+၊ screen-capture ခွင့်ပြုချက် dialog လိုပြီး engine အချို့ ပိတ်ထား။
- **MediaStore (Music folder) သို့ ထုတ်ခြင်း (plugin ၏ ပုံသေ):** အသုံးပြုသူ၏ Music တွင် ဖိုင်ကျန်ပြီး ကိုယ်ရေးကိုယ်တာ စာသား၏ အသံ ပေါက်ကြားနိုင်။

## Consequences

- Play/Download ကို ပထမဆုံး နှိပ်ချိန်တွင် engine ထုတ်ပြီးသည်အထိ (offline engine တွင် များသောအားဖြင့် စက္ကန့်အနည်းငယ်) စောင့်ရမည်။
  ⚠️ လက်ခံနိုင်သော စောင့်ချိန် မသတ်မှတ်ရသေး — ဖုန်းပေါ်တွင် engine အလိုက် တိုင်းရန်။
- Android engine ၏ ပထမ ဖတ်ခြင်း (speaker) တွင် waveform/playhead/pause မရ — ဖိုင်ထုတ်ပြီးမှ ရသည်။
- ဖိုင်သည် engine ကို ထပ်ခိုင်း၍ ရသော အသံဖြစ်ပြီး ကြားခဲ့သော အသံနှင့် တူမည်ဟု ယူဆသည် (engine အများစုသည် စာ/setting တူလျှင် တူညီ)။
  ⚠️ Online/random ပါဝင်သော voice တွင် အနည်းငယ် ကွဲနိုင်ခြင်းကို မစစ်ရသေး။
- ယာယီဖိုင်တွင် နောက်ဆုံးအသံ တစ်ခု app cache ထဲ ကျန်သည် (နောက်ထုတ်ချိန်တွင် အစားထိုး၊ OS က cache ရှင်းနိုင်)။
- ⚠️ SM Myanmar TTS စသော engine အလိုက် ဖိုင်ထုတ်နိုင်မှုကို ဖုန်းပေါ်တွင် မစမ်းရသေး — Linux ပေါ်တွင် flutter_tts မရ၍
  mock channel ဖြင့်သာ test လုပ်ထားသည်။

## Rollback plan

ဤ commit ကို revert ပြုပါ။ Data/schema ပြောင်းလဲမှု မရှိ။ ယာယီဖိုင်သည် app cache တွင်သာ ရှိ၍ ကျန်ခဲ့လည်း OS က ရှင်းသည်။
