# Design Inputs — မြန်မာ စာမှ အသံ (Android)

ISO 9001:2015 အပိုဒ် 8.3.3 အရ ဤ feature က ဖြည့်ဆည်းရမည့် လိုအပ်ချက်များကို မှတ်တမ်းတင်ထားခြင်း။

## 1. Functional / performance requirements

- Android စက်ပေါ်တွင် အသုံးပြုသူ ရိုက်ထည့်သော မြန်မာစာ (Unicode) ကို အသံထွက်ဖတ်ပြရမည်။
- စက်တွင် ထည့်ထားသော TTS engine အားလုံးကို မစစ်ထုတ်ဘဲ ပြရမည်၊ ပုံသေ engine သည် ဖုန်းပေါ် MyanmarTTS ဖြစ်ရမည် (ADR 0004)။
- Engine ရွေးတိုင်း ထို engine ပံ့ပိုးသော ဘာသာစကားများကို ပြပြီး အသုံးပြုသူ ရွေးနိုင်ရမည် — ပုံသေ မြန်မာ (ရှိပါက)။
- Android engine (ဥပမာ Google TTS) တွင် ရွေးထားသော ဘာသာ၏ ထည့်သွင်းပြီး အသံများထဲမှ ရွေးနိုင်ရမည် — ပုံသေ = engine ၏ အသံ၊
  online အသံကို မှတ်ပြရမည်၊ လက်မခံသော အသံကို ပုံသေသို့ ပြန်ထားပြီး အကြောင်းရင်း ပြရမည်။
- Engine က ဘာသာ မပေးပါက သို့မဟုတ် ရွေးထားသော ဘာသာကို လက်မခံပါက ဖတ်ရန်ခလုတ်ကို ပိတ်ပြီး အကြောင်းရင်းကို ပြရမည်။
- Android engine တိုင်းတွင်လည်း waveform၊ player (pause/seek) နှင့် download ရရမည် — engine က WAV ဖိုင် ထုတ်နိုင်ပါက။
  Speak သည် ချက်ချင်း ဖတ်ရမည် (မစောင့်ရ)၊ Play/Download နှိပ်မှသာ ဖိုင်ထုတ်ရမည် (engine ကို အလကား နှစ်ခါ မခိုင်းရန်)။
  မထုတ်နိုင်ပါက အကြောင်းရင်း ပြပြီး Play/Download ကို ဖျောက်ရမည် (ADR 0005)။
- အမြန်နှုန်းနှင့် အသံအနိမ့်အမြင့်ကို ချိန်ညှိနိုင်ရမည်၊ ဖတ်နေစဉ် ရပ်နိုင်ရမည်။
- Engine ၏ input အရှည်ကန့်သတ်ချက် (Android ပုံသေ 4000 လုံး) ထက် ရှည်သော စာကို engine သို့ မပို့မီ ငြင်းရမည်။
- ⚠️ DETERMINATION REQUIRED — Engine ပြောင်းချိန် (engine initialize + ဘာသာစာရင်း ယူ) အတွက် လက်ခံနိုင်သော အချိန်ကန့်သတ်ချက် မသတ်မှတ်ရသေးပါ။

## 2. Information from previous similar designs

- **Not applicable** — ဤ repository ၏ ပထမဆုံး feature ဖြစ်ပြီး ယခင် TTS ဒီဇိုင်း မရှိပါ။
- ပြင်ပ ရည်ညွှန်းချက်: `flutter_tts` 4.2.5 ၏ Android source ကို ဖတ်ပြီး အောက်ပါအချက်များကို အတည်ပြုထားသည် —
  `setEngine` သည် engine initialize ပြီးမှ ပြန်လာသည်၊ `stop` သည် ဆိုင်းငံ့နေသော `speak` ကို `0` ဖြင့် ပြီးစေသည်၊
  speech rate `0.5` သည် Android ၏ ပုံမှန်နှုန်း `1.0` နှင့် ညီသည်။

## 3. Statutory / regulatory requirements

- ⚠️ DETERMINATION REQUIRED — App ကို ထုတ်ဝေမည့် ဈေးကွက်/ဥပဒေ (ဥပမာ accessibility ဥပဒေ) မသတ်မှတ်ရသေးပါ။
- စာသားကို စက်ပေါ်ရှိ engine သို့သာ ပို့သည်။ App ကိုယ်တိုင် network သို့ မပို့ပါ။ သို့သော် engine အချို့
  (network voice) က စာသားကို ၎င်းတို့ server သို့ ပို့နိုင်သည် — privacy ဆိုင်ရာ ဆုံးဖြတ်ချက် လိုအပ်နိုင်သည်။

## 4. Standards committed to

- ISO 9001:2015 (အဖွဲ့အစည်း coding standard အတိုင်း)။
- Burmese စာကို Unicode (U+1000–U+109F) အဖြစ်သာ လက်ခံသည်။ Zawgyi encoding ကို မပံ့ပိုးပါ။
- ဘာသာစကားကို BCP 47 language tag (Android `Locale.toLanguageTag()`) ဖြင့် ဖော်ပြသည်။
- Android 11+ package visibility — `AndroidManifest.xml` တွင် `TTS_SERVICE` query ကြေညာထားသည်။

## 5. Potential consequences of failure

- ရွေးထားသော ဘာသာနှင့် ရိုက်ထားသော စာ မကိုက်ပါက (ဥပမာ `en-US` ဖြင့် မြန်မာစာ) engine က မှားဖတ်ခြင်း သို့မဟုတ်
  အသံမထွက်ခြင်း ဖြစ်မည် — Android engine များအတွက် app က မစစ်သဖြင့် ဘာသာ dropdown ကို engine အောက်တွင် ထင်ရှားစွာ ပြရမည်။
- Engine က ဘာသာ မရှိ/လက်မခံသည်ကို မပြပါက အသုံးပြုသူက app ပျက်နေသည်ဟု ယူဆမည်။
- Data မဒေါင်းရသေးသော သို့မဟုတ် online အသံကို internet မရှိချိန် ရွေးပါက အသံမထွက်ဘဲ ငြိမ်နေမည် — ဖယ်/မှတ်ပြ ရမည်။
- Engine က ဖိုင်ထုတ်မှု မပံ့ပိုးပါက flutter_tts သည် callback မပို့ — ကန့်သတ်ချိန် မထားပါက "ဖတ်ပါ" နှိပ်ပြီး app သည် ထာဝရ စောင့်နေမည်။
- Engine ၏ ယာယီ WAV ဖိုင်ကို တစ်ခုတည်း အစားထိုးမသုံးပါက ဖတ်တိုင်း storage စားမည်။ Engine က မရေးဘဲ "ပြီးပြီ" ဟုဆိုပါက
  ယခင်ဖိုင်ကို ဖတ်မိ၍ မှားသောစာ၏ အသံ ဖွင့်/download ပေးမိမည် — မထုတ်မီ ဖျက်ရမည်။
- Zawgyi ဖြင့် ရိုက်ထားသော စာကို Unicode engine က ဖတ်ပါက အဓိပ္ပါယ်မရှိသော အသံ ထွက်မည် —
  အမှား message မပေါ်ဘဲ ဖြစ်သဖြင့် အသုံးပြုသူ မသိနိုင်ပါ။
- အသုံးပြုသူကိုယ်တိုင် ရပ်ခြင်းကို အမှားအဖြစ် ပြပါက ယုံကြည်မှု ကျဆင်းပြီး မှားယွင်းသော bug report များ ဝင်လာမည်။
- Input အရှည်ကို မစစ်ပါက engine က အသံမထွက်ဘဲ ငြိမ်နေမည်။
